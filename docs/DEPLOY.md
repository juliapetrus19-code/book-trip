# BookTrip — как запустить сайт (инструкция для владельца)

Эта инструкция написана для человека без технического опыта. Вам понадобятся: аккаунт GitHub
(там уже лежит код сайта), банковская карта и примерно 30 минут.

Сайт работает в двух режимах:

| Режим | Что нужно | Что умеет |
|---|---|---|
| **Демо** | ничего | Только книги, которые встроены в сайт. Бесплатно. |
| **Живой режим** | ключ Anthropic (Claude) | Любая книга: пересказ, термины, персонажи, похожие книги, 3D-фильм. |
| **Портреты** | + ключ Google Gemini | AI-портрет любого персонажа. |
| **Видео (премиум)** | + ключ Gemini + секретный код `PREMIUM_CODE` | Настоящее AI-видео: 3 ролика по 8 секунд. |

Можно начать с демо, а ключи добавить позже — сайт сам поймёт, что они появились.

---

## 1. Ключ Anthropic (Claude) — для живого режима

1. Откройте **https://console.anthropic.com** и зарегистрируйтесь (можно через Google).
2. Пополните баланс: **Settings → Billing → Add credits** (Настройки → Оплата → Пополнить).
   Для начала достаточно $10–20. Ключ не работает, пока на балансе $0.
3. Поставьте лимит расходов, чтобы не было сюрпризов: **Settings → Limits** — например, $50 в месяц.
4. Создайте ключ: **API Keys → Create Key**. Назовите его, например, `booktrip`.
5. Скопируйте ключ (начинается с `sk-ant-…`) и сохраните в надёжном месте.
   **Ключ показывается только один раз.** Никому его не отправляйте и не публикуйте.

## 2. Ключ Google Gemini — для портретов и видео (по желанию)

1. Откройте **https://aistudio.google.com** и войдите с Google-аккаунтом.
2. Нажмите **Get API key → Create API key** (Получить ключ → Создать ключ).
3. Включите оплату: рядом с ключом нажмите **Set up billing** (Настроить оплату) и привяжите карту
   в Google Cloud. Без оплаты генерация картинок и видео не работает.
4. Рекомендуем в Google Cloud настроить бюджет с уведомлениями: **Billing → Budgets & alerts**.
5. Скопируйте ключ (начинается с `AIza…`) и сохраните его.

## 3. Секретные значения, которые вы придумываете сами

- **`SIGNING_SECRET`** — длинная случайная строка (40+ символов), которой сайт подписывает ссылки на
  портреты и видео, чтобы никто не мог пользоваться вашими ключами бесплатно. Сгенерируйте её
  любым генератором паролей (например, в вашем менеджере паролей). Посетителям её знать не нужно.
- **`PREMIUM_CODE`** — код доступа к AI-видео. Его вы выдаёте платным клиентам; они вводят его на
  сайте. Чтобы закрыть доступ всем старым клиентам — просто смените код. Если оставить пустым,
  видео полностью выключено (кнопка будет недоступна).

## 4. Публикация на Vercel

1. Откройте **https://vercel.com** и войдите через GitHub (**Continue with GitHub**).
2. Нажмите **Add New… → Project**, найдите репозиторий сайта и нажмите **Import**.
3. На экране настройки:
   - **Framework Preset**: `Other`;
   - **Build Command** и **Output Directory** оставьте пустыми — сборка не нужна.
4. Откройте раздел **Environment Variables** (переменные окружения) и добавьте по одной:

   | Name (имя) | Value (значение) | Обязательно? |
   |---|---|---|
   | `ANTHROPIC_API_KEY` | ваш ключ `sk-ant-…` | для живого режима |
   | `GEMINI_API_KEY` | ваш ключ `AIza…` | для портретов и видео |
   | `SIGNING_SECRET` | ваша случайная строка | очень желательно |
   | `PREMIUM_CODE` | ваш код доступа к видео | для видео |
   | `ANTHROPIC_MODEL` | не заполнять (по умолчанию `claude-opus-5-5`) | нет |
   | `BOOK_EFFORT` | не заполнять (`medium`); `high` — тщательнее, но дороже | нет |
   | `GEMINI_IMAGE_MODEL`, `GEMINI_VIDEO_MODEL` | не заполнять | нет |

5. Нажмите **Deploy** и подождите 1–2 минуты. Vercel покажет адрес сайта вида
   `https://booktrip-xxxx.vercel.app`.
6. Проверьте: откройте `https://ваш-сайт/api/health`. Должно быть что-то вроде
   `{"live":true,"portraits":true,"video":true,…}`. Ключи там никогда не показываются.

### Если ключи добавлены или изменены позже

Переменные применяются только к новым публикациям. После изменения откройте
**Deployments**, у последней публикации нажмите **⋯ → Redeploy**.

### Свой домен

**Project → Settings → Domains → Add** и следуйте подсказкам Vercel.

## 5. Сколько это стоит (примерно)

| Что | Цена |
|---|---|
| Claude Opus 5.5 | $4 за 1 млн входящих токенов и $20 за 1 млн исходящих |
| Одна новая книга целиком (поиск + пересказ + персонажи + фильм) | ≈ $0.15–0.35 **один раз** |
| Повторные открытия той же книги на том же языке | бесплатно: ответ кэшируется в базе Upstash (v2) и сетью Vercel для всех посетителей |
| Один AI-портрет персонажа | ≈ $0.04 (тоже кэшируется) |
| AI-видео (Veo 3.1 Fast, ≈ $0.10–0.12 за секунду) | 3 ролика × 8 с ≈ **$2.5–3** за одно видео |
| Хостинг Vercel | бесплатный тариф Hobby для старта; для коммерческого сайта нужен Pro |

Каждый язык (русский, украинский, английский) — отдельный ответ, поэтому одна книга на трёх языках
стоит примерно втрое дороже, но тоже только один раз. После нового деплоя кэш Vercel может начаться
заново — первые открытия популярных книг снова будут платными.

Видео — самая дорогая часть, поэтому оно доступно только с `PREMIUM_CODE`. Установите цену для
клиентов с запасом (например, от $5 за видео).

## 6. Защита от злоупотреблений (обязательно прочитайте)

Сайт уже ограничивает частоту запросов с одного адреса (≈30 книжных запросов и 10 портретов за
10 минут, 3 видео в час) и принимает на портреты и видео только подписанные сайтом описания. Но эти
счётчики живут в памяти серверов и сбрасываются, поэтому настройте ещё и защиту Vercel:

1. В проекте откройте **Firewall → Configure → New Rule** (Брандмауэр → Новое правило).
2. Правило «API»: **If** `Request Path` **starts with** `/api/` → **Then** `Rate Limit`,
   например 60 запросов за 60 секунд с одного IP; действие при превышении —
   `Too Many Requests (429)`.
3. Правило «Видео»: путь `/api/video` → 10 запросов за 10 минут.
4. Правило «Портреты»: путь `/api/portrait` → 20 запросов за 10 минут.
5. Нажмите **Save** и **Publish**.
6. Если видите всплеск подозрительного трафика — включите **Attack Challenge Mode** в том же разделе.

Также обязательно:

- лимит расходов в Anthropic (**Settings → Limits**) и бюджет в Google Cloud;
- в Vercel — **Settings → Billing → Spend Management**, чтобы хостинг не вышел за ваш бюджет;
- никогда не пишите ключи в код, в чаты и в письма — только в Environment Variables на Vercel.
  Если ключ утёк: удалите его в консоли Anthropic/Google, создайте новый, замените в Vercel и
  сделайте Redeploy.

## 7. Если что-то не работает

| Что видно | Что делать |
|---|---|
| `/api/health` показывает `"live": false` | Нет `ANTHROPIC_API_KEY` или не сделан Redeploy после добавления. |
| Сайт пишет, что живой режим не настроен, хотя ключ есть | Ключ неверный или закончились деньги на балансе Anthropic. |
| «Слишком много запросов» | Сработало ограничение частоты — подождите 10 минут. |
| Портреты не появляются | Проверьте `GEMINI_API_KEY` и что в Google включена оплата. |
| Видео недоступно | Нужны и `GEMINI_API_KEY`, и `PREMIUM_CODE`; клиент должен ввести верный код. |
| Ошибки в работе | Vercel → проект → **Logs**: там видны сообщения сервера (без ключей). |

## 8. BookTrip v2: аккаунты, «2 книги бесплатно, дальше подписка», общий кэш

Всё в этом разделе необязательно. **Без этих настроек сайт работает как раньше**: без входа,
без оплаты и без ограничений. Каждая функция включается сама, когда появляются её переменные.

| Что | Переменные | Что даёт |
|---|---|---|
| База Upstash Redis | `KV_REST_API_URL`, `KV_REST_API_TOKEN` (Vercel добавит сам) | общий кэш ответов ИИ (каждая книга генерируется один раз для всех), счётчики бесплатных книг, подписки, лист ожидания, статистика |
| Вход по ссылке на почту | `SIGNING_SECRET` + `RESEND_API_KEY` (+ `MAIL_FROM`) | аккаунты |
| Подписка Paddle | `PADDLE_*` (см. ниже) | платная подписка; **только тогда включается ограничение «N книг бесплатно»** |
| Прочее | `PUBLIC_TELEGRAM`, `ADMIN_TOKEN`, `SITE_URL`, `FREE_BOOKS`, `PRICE_LABEL_*` | кнопки «Написать нам», админ-статистика, адрес сайта, число бесплатных книг, цены на сайте |

Рекомендуемый порядок: 8.1 → 8.2 → 8.3 → 8.4 (sandbox, проверка) → 8.6 (боевой режим).

### 8.1. База данных Upstash (через Vercel Storage)

1. Vercel → ваш проект → вкладка **Storage** → **Create Database**.
2. Выберите **Upstash** → **Upstash for Redis** (Marketplace) → **Continue**.
3. Регион — ближайший к функциям проекта (например, Frankfurt), тариф **Free** для старта.
4. Нажмите **Create**, затем **Connect Project** и выберите проект BookTrip (все окружения).
5. Vercel сам добавит переменные `KV_REST_API_URL` и `KV_REST_API_TOKEN` (и ещё несколько — их
   трогать не нужно). Если вы создавали базу прямо на upstash.com, добавьте вручную
   `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN` из вкладки **REST API** — подходит любая пара.
6. Сделайте **Redeploy**. Проверка: `https://ваш-сайт/api/health` → `"store": "redis"`.

Без базы сайт использует память сервера: она сбрасывается при каждом перезапуске и не общая для
разных серверов — для настоящего запуска база обязательна.

### 8.2. Секрет подписи `SIGNING_SECRET` (обязательно для аккаунтов)

Этим секретом запечатываются cookie входа. Сгенерируйте случайную строку один раз:

```bash
openssl rand -base64 48
# или: node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"
```

Добавьте её в Vercel как `SIGNING_SECRET`. **Не меняйте её без нужды**: после смены все посетители
выйдут из аккаунтов, а старые ссылки на портреты и видео перестанут работать.

### 8.3. Письма для входа: Resend

1. Зарегистрируйтесь на **https://resend.com**.
2. **Domains → Add Domain** — укажите домен сайта (например, `booktrip.com.ua`) и добавьте у
   регистратора домена DNS-записи, которые покажет Resend (SPF/DKIM). Дождитесь статуса **Verified**.
3. **API Keys → Create API Key**, права **Sending access** → скопируйте ключ `re_…` →
   переменная `RESEND_API_KEY`.
4. `MAIL_FROM` — отправитель с вашего домена, например `BookTrip <login@booktrip.com.ua>`.
   Без своего домена можно оставить пусто (`onboarding@resend.dev`), но тогда Resend доставляет
   письма **только на почту владельца аккаунта Resend** — годится лишь для проверки.
5. Письмо приходит на языке, выбранном на сайте (украинский, русский или английский); ссылка
   действует 30 минут. Ограничения: не больше 5 писем в час на один адрес и 8 за 15 минут с одного IP.

> `AUTH_DEV_LINKS=1` — только для локальной разработки и тестов: ссылка входа возвращается прямо
> в ответе вместо письма. **Никогда не ставьте её на Vercel** — иначе любой войдёт под любым адресом.

Проверка: `/api/health` → `"account": true`.

### 8.4. Подписка: Paddle Billing (сначала sandbox)

Paddle — «продавец» (Merchant of Record): он принимает оплату, платит налоги, выставляет счета и
занимается возвратами. Страницы `/terms`, `/privacy`, `/refund` уже есть на сайте (черновики —
перечитайте их и поправьте под себя перед запуском; Paddle проверяет их при одобрении сайта).

1. Зарегистрируйте **тестовый** аккаунт: **https://sandbox-vendors.paddle.com/signup**.
2. **Catalog → Products → New product**: название «BookTrip Premium», налоговая категория —
   стандартные цифровые товары / SaaS. Сохраните.
3. В продукте **Prices → New price**:
   - ежемесячная: `4.99 USD`, **Billing period: every 1 month** (recurring);
   - ежегодная: `29 USD`, **every 1 year**.
   Скопируйте их ID (`pri_…`) → `PADDLE_PRICE_MONTH` и `PADDLE_PRICE_YEAR`. Можно сделать только
   одну из двух цен. Подписи цен на сайте — `PRICE_LABEL_MONTH` / `PRICE_LABEL_YEAR`
   (по умолчанию `$4.99` и `$29`; меняйте их вместе с ценами в Paddle).
4. **Developer Tools → Authentication**:
   - **Client-side tokens → New client-side token** → токен `test_…` → `PADDLE_CLIENT_TOKEN`
     (он публичный, его видит браузер — это нормально);
   - **API keys → New API key** → ключ → `PADDLE_API_KEY` (секретный; нужен для кнопки
     «Управлять подпиской»; если Paddle предлагает выбрать права — разрешите работу с клиентами
     и сессиями клиентского портала).
5. **Developer Tools → Notifications → New destination**:
   - **Type**: webhook; **URL**: `https://<ваш-домен>/api/billing/webhook`;
   - события: `subscription.created`, `subscription.updated`, `subscription.activated`,
     `subscription.canceled`, `subscription.past_due`, `subscription.paused`, `subscription.resumed`;
   - сохраните, откройте destination и скопируйте **Secret key** (`pdl_ntfset_…`) →
     `PADDLE_WEBHOOK_SECRET`.
6. **Checkout → Checkout settings → Default payment link**: `https://<ваш-домен>/` (без этого
   Paddle не откроет оплату на сайте).
7. В Vercel добавьте `PADDLE_ENV=sandbox` и все переменные выше, сделайте **Redeploy**.
8. Проверка: `/api/health` → `"billing": { "enabled": true, "env": "sandbox", … }`. Откройте сайт
   в режиме инкогнито, откройте 3 книги — на третьей появится предложение подписки. Войдите по
   почте, оплатите тестовой картой `4242 4242 4242 4242`, срок — любая будущая дата, CVC `100`.
   Через несколько секунд книги снова открываются без ограничений. В Paddle →
   **Notifications → Logs** видно, что webhook доставлен (статус 200).

Как это работает: оплата привязывается к аккаунту (почте). Отменить подписку пользователь может сам
кнопкой «Управлять подпиской» (портал Paddle) — доступ остаётся до конца оплаченного периода.
Бесплатные книги считаются по посетителю (cookie) и по аккаунту; после входа уже открытые книги
переходят в аккаунт, так что вход не даёт новых бесплатных книг. Число бесплатных книг — `FREE_BOOKS`
(по умолчанию 2).

### 8.5. Telegram, адрес сайта и админ-статистика

- `PUBLIC_TELEGRAM` — имя пользователя или канала в Telegram **без @** (например, `booktrip_ua`):
  кнопки «Написать нам» на сайте и ссылки на страницах условий.
- `SITE_URL` — основной адрес сайта, например `https://booktrip.com.ua` (для ссылок в письмах,
  `sitemap.xml`, `robots.txt` и SEO-тегов). Если пусто — берётся адрес, по которому пришёл запрос.
- `ADMIN_TOKEN` — длинная случайная строка (сгенерируйте как `SIGNING_SECRET`). Включает
  `GET /api/admin`: лист ожидания (самые запрашиваемые книги и последние заявки), события по дням
  за 30 дней, число пользователей и подписчиков. Посмотреть:

  ```bash
  curl -s -H "x-admin-token: ВАШ_ADMIN_TOKEN" https://ваш-сайт/api/admin | python3 -m json.tool
  ```

  Без `ADMIN_TOKEN` адрес отвечает 404, с неверным токеном — 403 (и после 10 ошибок за час с одного
  IP — временная блокировка).

### 8.6. Боевой режим Paddle

1. Зарегистрируйте **боевой** аккаунт на **https://vendors.paddle.com/signup** и пройдите проверку
   (данные бизнеса, проверка сайта — Paddle смотрит на `/terms`, `/privacy`, `/refund` и цены).
2. Повторите шаги 8.4.2–8.4.6 в боевом аккаунте: новые продукт и цены, client-side token (`live_…`),
   API key, notification destination с новым секретом, default payment link.
3. В Vercel замените все `PADDLE_*` на боевые значения и поставьте `PADDLE_ENV=production`.
   Убедитесь, что `AUTH_DEV_LINKS` **не задан**. Сделайте **Redeploy**.
4. Проверка: `/api/health` → `"billing": { "enabled": true, "env": "production", … }`.

### 8.7. SEO

Каждая книга теперь имеет свой адрес `https://ваш-сайт/book/<id>` с собственным заголовком,
описанием и превью для соцсетей. Карта сайта — `/sitemap.xml` (встроенные книги и все книги,
для которых уже создан пересказ), `robots.txt` ссылается на неё. Добавьте сайт в
**Google Search Console** и отправьте `https://ваш-сайт/sitemap.xml`.

### 8.8. Что добавить в Firewall (к разделу 6)

- `/api/auth/start` → 10 запросов за 10 минут с одного IP;
- `/api/waitlist` и `/api/event` → 60 запросов за 10 минут.

### 8.9. Если что-то не работает (v2)

| Что видно | Что делать |
|---|---|
| `/api/health` → `"store": "memory"` | Не подключена база Upstash или не сделан Redeploy (8.1). |
| `"account": false` | Нет `SIGNING_SECRET` или `RESEND_API_KEY` (8.2, 8.3). |
| Письмо не приходит | Resend → **Emails**: статус письма. Без своего домена письма идут только владельцу Resend. Проверьте «Спам». |
| `"billing": { "enabled": false }` | Нужны `PADDLE_CLIENT_TOKEN`, хотя бы одна цена `PADDLE_PRICE_*`, `PADDLE_WEBHOOK_SECRET`, `SIGNING_SECRET` и (на Vercel) подключённая база Upstash — без неё оплата не включается, чтобы подписчики не упёрлись в ограничение. |
| Оплатил, но книги закрыты | Paddle → **Notifications → Logs**: webhook должен получать 200. 401 — неверный `PADDLE_WEBHOOK_SECRET` (или sandbox-секрет в боевом режиме). Проверьте адрес `/api/billing/webhook`. |
| «Управлять подпиской» не работает | Нужен `PADDLE_API_KEY` того же окружения (sandbox/production). |


## 9. Аниме-картинки персонажей и фильма — бесплатно

Персонажи и мини-фильм могут выглядеть как аниме: нарисованные портреты и кадры с движением камеры.
Платить за это не нужно.

**Без настройки** картинки рисует сервис Pollinations.ai прямо в браузере посетителя: бесплатно, без ключа,
но медленно (примерно одна картинка в 15 секунд), иногда с маленьким водяным знаком. Пока картинка рисуется,
на её месте видна 3D-фигурка, так что пустых мест на странице нет.

**Быстро и без водяного знака — через Cloudflare (тоже бесплатно, 2 минуты):**
1. Зарегистрируйтесь на https://dash.cloudflare.com/sign-up (бесплатный тариф, карта не нужна).
2. Слева выберите **AI → Workers AI**, нажмите **Use REST API**.
3. **Create a Workers AI API Token** → **Create API Token** → скопируйте токен.
4. На той же странице скопируйте **Account ID**.
5. В Vercel → Settings → Environment Variables добавьте:
   | Имя | Значение |
   |---|---|
   | `CLOUDFLARE_ACCOUNT_ID` | Account ID |
   | `CLOUDFLARE_API_TOKEN` | токен |
6. **Redeploy.**

Бесплатного лимита Cloudflare (10 000 «нейронов» в день) хватает примерно на несколько сотен или тысяч картинок в сутки.
Картинку для каждого героя и кадра сервер рисует **один раз**, дальше её отдаёт кэш Vercel — повторные
просмотры лимит не тратят. Сайт сам не нарисует больше `ANIME_DAILY_CAP` картинок в день (по умолчанию 1500).
Если лимит кончился, картинки дорисует Pollinations в браузере.

Посетитель может переключить вид «Аниме / 3D» на странице книги. Полностью выключить аниме: `ANIME_PROVIDER=off`.
