# BookTrip — путешествие внутрь любой книги

**BookTrip** — сайт, на котором можно «войти» в книгу. Посетитель вводит название, а сайт за минуту
показывает:

- **пересказ** — связный, со спойлерами, на 4–7 абзацев, с кнопкой «Слушать» (озвучка браузером);
- **словарь книги** — важные имена, места и понятия с поиском;
- **всех заметных персонажей** — каждый в виде милой воксельной 3D-фигурки, которую можно покрутить;
- **похожие книги** — что почитать дальше и почему;
- **3D мини-фильм «Путешествие в книгу»** — книга раскрывается, камера ныряет внутрь, и зритель
  проходит через 5–7 ключевых сцен с субтитрами и озвучкой;
- **премиум**: AI-портрет любого героя (модель изображений Google Gemini) и настоящее AI-видео —
  три 8-секундных ролика по сценам книги (модель Veo).

Сайт работает на трёх языках — **русском, украинском и английском** — и одинаково хорошо выглядит на
телефоне (от 320 px) и на большом мониторе (до 2560 px).

## Демо-режим и живой режим

| Режим | Что нужно | Что умеет |
|---|---|---|
| **Демо** | ничего | 12 встроенных книг с полностью готовыми материалами. Работает даже на простом статическом хостинге, без серверных функций. |
| **Живой режим** | ключ Anthropic (Claude) | Любая книга мира: ИИ находит её, пишет пересказ, термины, персонажей, похожие книги и сценарий фильма. |
| **AI-портреты** | + ключ Google Gemini | Живописный портрет персонажа по описанию из книги. |
| **AI-видео (премиум)** | + ключ Gemini + секретный код `PREMIUM_CODE` | Три настоящих видеоклипа по сценам книги. |

Сайт сам определяет режим: при загрузке он спрашивает `/api/health`, какие ключи подключены.
Без ключей поиск работает по встроенной библиотеке (с опечатками, на любом из трёх языков), а на
незнакомую книгу показывает понятное сообщение и предлагает книги из библиотеки.

В живом режиме ответы ИИ кэшируются дважды: на CDN Vercel (повторный запрос той же книги не стоит
денег) и в браузере посетителя. Ошибки не кэшируются никогда.

Встроенные книги: «Маленький принц», «Гарри Поттер и философский камень», «Алиса в Стране чудес»,
«Хоббит», «1984», «Гордость и предубеждение», «Собака Баскервилей», «Великий Гэтсби»,
«Три мушкетёра», «Остров сокровищ», «Тени забытых предков», «Ромео и Джульетта».

## BookTrip v2: аккаунты, подписка, общий кэш

Всё включается переменными окружения и выключено по умолчанию — **без ключей сайт работает как v1**
(подробная инструкция — `docs/DEPLOY.md`, раздел 8; договор клиента и сервера — `docs/V2-CONTRACT.md`).

- **Общий кэш ИИ** (Upstash Redis, `KV_REST_API_*`): каждая книга генерируется один раз для всех
  посетителей; без базы — память сервера.
- **Вход по ссылке на почту** (`SIGNING_SECRET` + Resend): `/api/auth/start`, `/api/auth/verify`,
  `/api/auth/logout`, `/api/me`.
- **«2 книги бесплатно, дальше подписка»** (Paddle Billing, `PADDLE_*`): `/api/access`,
  `/api/billing/checkout`, `/api/billing/portal`, webhook `/api/billing/webhook`. ИИ-части книги
  (пересказ, персонажи, фильм, портреты) закрываются на сервере ответом 402.
- **Лист ожидания и воронка**: `/api/waitlist`, `/api/event`; статистика — `/api/admin`
  (заголовок `x-admin-token`).
- **SEO**: страницы `/book/<id>` с собственными мета-тегами и текстом, `/sitemap.xml`, `/robots.txt`;
  юридические страницы `/terms`, `/privacy`, `/refund` (черновики).

Локально: `SIGNING_SECRET=dev AUTH_DEV_LINKS=1 npm run dev` — ссылка входа возвращается в ответе
вместо письма (только для разработки).

## Как запустить у себя на компьютере

Нужен **Node.js 20 или новее** (https://nodejs.org).

```bash
npm install          # один раз: зависимости сервера (Anthropic SDK)
npm run dev          # сайт на http://localhost:5600 (демо-режим)
```

Откройте **http://localhost:5600** в браузере. Сервер разработки отдаёт файлы сайта и выполняет
функции из папки `api/` точно так же, как это делает Vercel.

**Живой режим локально:** скопируйте `.env.example` в `.env`, впишите ключи и запустите

```bash
npm run dev:env      # то же самое, но с переменными из .env
```

Файл `.env` никогда не попадает в git (он в `.gitignore`), а ключи никогда не уходят в браузер —
их читают только серверные функции.

### Проверки

```bash
npm test                 # тесты API (без настоящих ключей — всё на заглушках)
npm run validate         # проверка всех книг в data/books/*.json по контракту из SPEC.md
npm run build:catalog    # пересобрать data/catalog.json после изменения книг
npm run e2e              # сквозная проверка сайта в браузере (см. ниже)
```

Сквозная проверка `tests/e2e.mjs` открывает сайт в Chromium и проходит всё: главную, поиск и
подсказки, полку обложек, страницу книги, 3D-фигурки всех персонажей всех книг, 3D-просмотр,
фильм (сцены, субтитры, пауза, перезапуск, финал), переключение языков, разделы «Как это работает»,
«Библиотека», «Премиум», кнопку «Назад», телефоны 390 и 320 px и живой режим на подставных ответах
API (включая ошибки и повтор). Для неё нужен Playwright:
`npm i -g playwright && npx playwright install chromium`, затем
`NODE_PATH=$(npm root -g) npm run e2e`. Если сервер разработки не запущен, тест запустит его сам.
Ключ `--shots` сохраняет снимки экрана в `shots/e2e/`.

## Как добавить демо-книгу

1. **Скопируйте** любую книгу из `data/books/`, например `data/books/the-hobbit.json`, в новый файл
   `data/books/<id>.json`. `<id>` — латиница, цифры и дефисы, например `war-and-peace`; он же
   записывается в поле `"id"` внутри файла.
2. **Заполните общие поля:** `year` (год; до нашей эры — отрицательное число), `cover` (цвета обложки
   `#rrggbb` и мотив из списка `COVER_MOTIFS` в `js/enums.js`), `aliases` — другие написания
   названия для поиска (транслитерация, короткое название).
3. **Тексты на трёх языках** — в `i18n.ru`, `i18n.uk`, `i18n.en`: название, автор, жанр, слоган
   (до 120 символов), пересказ (4–7 абзацев по 50–110 слов), темы (3–6), термины (6–14),
   похожие книги (4–6), тексты сцен фильма и имена/черты/описания персонажей.
4. **Персонажи** (`characters`, 4–14 штук, главные — первыми): у каждого `id`, роль и `appearance` —
   описание внешности для 3D-фигурки. Все допустимые значения (существо, причёска, одежда,
   головной убор, предмет в руке…) перечислены в `js/enums.js` и в `SPEC.md`, раздел 2.4.
   `portraitPrompt` — 1–2 предложения по-английски о внешности (для AI-портрета).
5. **Фильм** (`film`): 5–7 сцен по порядку сюжета — место действия, время суток, погода, кто в кадре
   (`cast` — id персонажей), предметы, действие, движение камеры, настроение, реплика; и ровно
   3 английских описания для AI-видео (`videoPrompts`).
6. **Проверьте и подключите:**
   ```bash
   npm run validate         # покажет, что не так, с точным путём к полю
   npm run build:catalog    # книга появится на полке, в поиске и в библиотеке
   ```
7. **Посмотрите результат:** `http://localhost:5600/#/book/<id>` — или страница разработчика
   `http://localhost:5600/dev/book.html?demo=<id>&lang=uk`. Фигурки удобно подбирать в
   `dev/voxel.html`. Сквозная проверка `npm run e2e` сама пройдёт по всем персонажам новой книги.

Подробный формат файла — в `SPEC.md`, раздел 2.7.

## Безопасность

- Ключи Anthropic и Google хранятся только в переменных окружения Vercel и никогда не попадают
  в браузер.
- Запросы на портреты и видео принимаются только с подписанными сервером описаниями — сайт нельзя
  использовать как бесплатный генератор картинок и видео.
- Лимиты запросов на каждый IP-адрес; перебор премиум-кода блокируется.
- Все тексты от ИИ и из файлов книг выводятся как обычный текст (без HTML), поэтому внедрить код
  через ответ модели нельзя.

## Известные ограничения

- Озвучка («Слушать», голос в фильме) использует голоса, встроенные в браузер/систему; если голоса
  для языка нет, озвучка молча пропускается, а субтитры остаются.
- 3D-графика требует WebGL; без него вместо 3D-фигурок рисуются плоские изображения, а фильм
  показывается раскадровкой.
- Отражения обложек на полке не видны в Firefox (он не поддерживает `-webkit-box-reflect`).
- Лимиты запросов хранятся в памяти каждой серверной функции и поэтому ориентировочные; для
  строгой защиты в `docs/DEPLOY.md` описаны правила Vercel Firewall.
- Ссылки на готовые AI-видео живут около 47 часов (столько Google хранит файлы).
